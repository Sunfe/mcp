# 知识库扩展项目：Feature 拆分与协作方案

日期：2026-11-20。状态：拆分完成，第一批 F00 工具已实现，经独立 QA、Chat1 A-01 及项目层集成核对通过；完整 F00 / M0 待真实资料与目标就绪。

## 1. 项目目标

扩展现有 MCP 知识库，支持大量 DOCX、PDF、TXT、图片与视频的可靠增量处理，提高检索质量，并提供可核对的来源、运行监控和恢复能力。

当前源码基础：`app/parsers.py` 提取纯文本，DOCX 只读段落；`app/ingest.py` 固定字符分块、全目录扫描、串行入库和删除；`app/db.py` 使用 SQLite FTS5；`app/search.py` 没有显式相关性排序或分页；`app/main.py` 直接执行重建任务。已有查询和 MCP 单元测试，但没有容量或质量基线。

用户已确认目标资料体量约 20 GB、日增量很少可忽略，首版单人使用，并要求预留多人接口。文件数量、格式构成、响应时间、部署资源、离线要求、预算与交付日期仍待 F00 收敛。数据库和模型尚未选定；资料体量不等于索引/模型/备份的磁盘预算。

## 2. 每个 Feature 的组织

```text
项目总台账（本会话）
  ├─ Fxx Chat1：该 feature 总调度
  │    └─ Fxx Chat2：设计＋编码
  │          └─ Fxx QA subagent：独立测试
  └─ 其他 feature 使用同样结构
```

| 参与者 | 职责 | 交付 |
|---|---|---|
| 项目总台账 | 优先级、跨 feature 依赖/接口、集成和里程碑 | 总台账、跨 feature 决策、发布范围 |
| Chat1 | 澄清范围、接受设计、安排修复、核对 QA 证据、验收 | feature.md、acceptance.md |
| Chat2 | 设计实现、自测、迁移文档、创建 QA subagent、修复 | design.md、实现、迁移/回滚说明 |
| QA subagent | 独立测试、缺陷复现、复测、证据记录 | qa-report.md、必要测试与证据 |

Chat1/Chat2 是独立聊天，QA 在 Chat2 内创建。QA 默认只读产品代码；需要写测试时分配独立文件。Chat1 直接读取测试报告，不以 Chat2 自报完成代替验收。设计编码者不能批准自己的最终验收。

建议按依赖分批启动，先激活 F00，后续默认一组 feature，资源允许再增加并行组数。当前根会话原生代理并发槽位为 4，其他聊天额度启动时确认，不承诺全部聊天同时执行。

## 4. Feature 范围、交付和验收

### F00 容量画像与质量评测

- 范围与交付：统计文件/页数、扫描比例、图片数、视频小时数、日增量、并发与硬件；建立查询集、指标字典、压测入口和当前基线。建议从 100–300 个代表性问题起步，实际规模由 F00 确认。
- 验收：可重跑；记录代码、语料、硬件和命令；覆盖参数编号、中文问法、表格、相似型号和无答案；明确 Recall@K、MRR 或 nDCG、P95、吞吐和峰值内存；调优前冻结目标阈值。
- QA：用已知好坏结果验证评测可区分质量；保留未参与调参的题集。用户原件不提交 Git。
- 所有权：新增评测和样本元数据，不修改生产索引。

### F01 文档身份、版本与来源契约

- 范围与交付：稳定 ID、来源 URI、哈希、版本、结构块、章节、页码、表格、图片区域、视频时间；解析/任务/检索接口；旧库迁移、回滚和 MCP 兼容设计。
- 验收：明确改名、复制和更新规则；新旧版本不混查；Windows/WSL 来源可映射；旧 ID 保留或提供映射；副本迁移后可恢复。
- QA：重复导入、改名、内容更新、缺失来源、旧库升级，引用不得指向错误版本。
- 所有权：`app/db.py`、`app/schemas.py` 及迁移/领域模型。公共接口变更由项目总台账协调。

### F02 可恢复的增量索引任务

- 范围与交付：持久化任务、流式发现、阶段执行、限流、重试/超时/取消、哈希缓存、幂等和版本发布；任务接口、worker、恢复说明。
- 验收：重复任务无重复片段；中断可恢复；来源不可访问不批量删除旧资料；新版本失败时旧版本可查；删除限定在完整扫描的来源范围。
- QA：终止 worker、重复投递、坏文件、目录不可用、取消、解析器升级；核对状态和数据库实际内容。
- 所有权：拆分 `app/ingest.py` 的调度与写入；队列选型依据 F00。

### F03 DOCX/PDF/TXT 结构化解析

- 范围与交付：编码、标题、段落、表格、阅读顺序、页码/结构锚点、结构分块；解析器适配层和金标准样本；识别扫描区域供 F07 处理。
- 验收：表头/单位/数值对应正确；长表跨页规则明确；标题关联正文；出处可核验；损坏或加密文件有状态。DOCX 等未分页格式不编造页码。
- QA：跨页表格、页眉页脚、中英文、编码异常、空文档和混合 PDF；人工核对结构。OCR 实现属于 F07。
- 所有权：`app/parsers.py` 和解析/分块模块，调度与持久化归 F02。

### F04 中文与参数精确检索

- 范围与交付：相关性排序、中文查询策略、参数/型号字段、标题权重、过滤和归一化；候选分值接口及对照评测。
- 验收：保留 `P5-35` 等现有回归行为；型号和版本过滤正确；排序稳定；中文/参数分组指标达标；特殊符号不会导致查询错误。
- QA：参数变体、多词、中文问句、相似型号、多版本和无结果，用独立题集验收。
- 所有权：`app/search.py` 词法策略，向 F05 输出候选，不混入模型推理。

### F05 语义混合检索与重排序

- 范围与交付：Embedding 版本、向量索引、词法/语义融合、去重、重排、上下文补充和降级；模型选择及质量/成本报告。
- 验收：相对 F04 达到语义改善目标，精确编号在允许退化范围内；过滤一致；模型失败有降级；不混用不兼容向量。
- QA：同义问法、中英文、重复候选、向量缺失、重排超时和模型升级；召回与排序分开评价。
- 所有权：新增向量/融合/重排模块，接入 F02 增量任务。

### F06 MCP 分页、片段读取与引用

- 范围与交付：列表分页、过滤、片段及相邻上下文、页/时间区间、输出预算和引用；兼容旧工具。
- 验收：大列表不全量加载；响应符合预算；提供继续读取标识；来源匹配版本；真实 Codex 完成搜索、读取和引用。
- QA：跨页、更新期间的分页语义、超大文档、失效片段、错误输入；工具可见不等于调用成功。
- 所有权：`app/mcp_server.py`、`app/main.py` 和读取层，遵循 F01 契约。

### F07 图片与扫描件检索

- 范围与交付：图片/PDF 区域 OCR、质量信号、视觉描述、原图定位；图文向量是否首版交付由查询场景决定。
- 验收：样本参数/单位准确率达标；OCR、模型描述、人工修正可区分；原图区域可定位；失败不伪装成空文本成功。
- QA：旋转、低清、小字、截图表格、接线图、无字图片；检查描述编造。若包含混合语义查询，追加 F05 依赖。
- 所有权：图像/OCR 适配器，复用 F02/F03/F06。

### F08 视频检索与时间定位

- 范围与交付：字幕、转写、关键帧、画面文字/描述、时间对齐、区间索引与预算控制。
- 验收：标准片段可召回，定位误差达标；长视频分段恢复；无字幕/音轨有策略；复用已有衍生结果。
- QA：静音、字幕偏移、中英文、长视频、坏片段和重复画面；核对原视频时间。跨模态语义场景追加 F05 依赖。
- 所有权：视频适配器，图像复用 F07，任务复用 F02。

### F09 大容量存储与查询扩展

- 范围与交付：按负载选择元数据/对象/检索存储，批量写入、分页、必要分片/副本、容量预算、迁移与回退。
- 验收：目标规模/并发/索引时效/P95 达标；旧新后端语义一致；迁移后 ID、版本和来源完整。
- QA：目标规模实测、并发读写、后端故障、磁盘压力、冷启动和回退，不以小样本外推为验收。
- 所有权：存储适配器与部署；F00 即开始容量探测，正式切换等 F05/F06 稳定。

### F10 多用户权限与资料隔离

- 范围与交付：身份到资料域、检索前过滤、读取校验、缓存隔离、审计和撤权；权限矩阵及隔离测试。
- 验收：未授权正文、摘要、标题、统计和缓存不泄露；撤权按约定时效生效；授权用户功能正确。
- QA：双用户/双资料域、共享文档、猜测 ID、缓存与权限变化；F05/F09 集成后重跑。
- 所有权：`app/auth.py` 和授权契约，各后端落实过滤。单用户首版可延后，多用户发布必须完成。

### F11 监控、备份恢复与发布验收

- 范围与交付：日志、阶段耗时、失败率、积压、容量、备份恢复、升级回退、平台矩阵和运行手册。
- 验收：独立环境恢复后资料/检索一致；中断升级可回退；区分 API 存活与索引就绪；日志不含凭据；声明支持的平台逐项记录实测或未验证。
- QA：中断、坏备份、模型缺失、目录不可用、重启、升级和真实客户端查询，使用测试副本。
- 所有权：部署/运维和监控；最终发布还依赖本次发布范围内所有 feature 完成。

## 6. 状态与验收

状态：Backlog → Ready → Design → Implementing → Testing → Acceptance → Done。阻塞记录 Blocked、原阶段、原因、解除条件与负责人，解除后回原阶段。

Ready 要求范围、依赖、样本、验收矩阵和所有权明确。实现前由 Chat1 接受设计，跨 feature/预算变更由总台账协调。

Done 要求：实现、设计、迁移/回滚和文档齐全；QA 有命令、环境、结果和被测版本；每项验收有证据；阻断缺陷归零；Chat1 复核并接受；集成后相关检查通过。未执行不能算通过，集成前最多为 Acceptance。

提交/合并/推送和发布依用户明确授权执行，本规划不授权生产数据迁移或外部发布。

## 7. 协作规则与台账

- feature 启动时创建 `docs/features/Fxx/feature.md`、`design.md`、`qa-report.md`、`acceptance.md`，使用配套模板。
- 并行实现使用独立工作树，基于上游已集成版本；保留当前未提交改动，不覆盖旧部署文件。
- Chat2 负责产品实现，QA 只写指定测试/证据目录，不同时修改同一文件。
- 公共 schema 归 F01，调度归 F02，内容归 F03，词法归 F04，融合归 F05，MCP 归 F06；跨界变更提交接口决定。
- 聊天 ID、工作树、测试代理只记录真实结果。启动时明确 Chat1/Chat2 消息授权，不虚构已运行团队。
- 文件保留需求、决定和证据，聊天用于沟通。进度按验收结果计算，不按代码量或聊天数计算。

当前 F00 为 Acceptance（工具阶段 PASS；完整容量与真实质量资料待就绪）：Chat2 已实现工具，其内部独立 QA 已完成，Chat1 A-01 正式验收工具，项目层已核对集成证据。F01–F11 为 Backlog。第一批仅启动 F00，后续 feature 等上游完整出口或明确的依赖范围调整。

### 需求确认 R-01（2026-11-20）

用户原话：“预计文件总量大约20G, 日增量少可忽略不计, 暂定单人使用, 你可以把多人使用的接口留出来.”

- 规划暂按约 20 GB 原始资料理解，不把体量换算成文件数，也不将 GB/GiB 差异当成已经精确确认。
- 低增量、单人本地使用优先；保留手工增量处理与可靠恢复能力，暂不因假设的高并发引入分布式设施。
- F01 的身份/来源契约预留主体与资料域上下文，F06 的调用上下文兼容扩展；首版默认本地主体。实际多用户身份验证、授权、撤权和泄漏隔离仍属于 F10，上线多人前必须验收，不能把预留字段视为权限实现。
- 图片/视频首版范围、实际文件数与格式构成、质量标签、延迟目标、预算和离线/恢复要求仍待定。现有一本手册的测量不能代替 20 GB 数据上的验证。
- Chat1/Chat2 继续完成 F00 工具、独立 QA 与基线证据；生产代表性和未确认阈值单列缺口，不阻止本次工具实施。

用户随后确认约 20 GB 资料“尚未整理好”，本轮使用现有手册和原创合成数据完成工具验收。完整语料清单、代表性标签和目标容量实测留待资料就绪后补齐；不扫描猜测目录，也不以合成小样本宣称 20 GB 验收通过。
