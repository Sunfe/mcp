# Feature 协作模板

配套 [项目拆分方案](knowledge-platform-project.md)。占位符须在启动前替换，不作为真实聊天 ID 或工作树使用。

## Feature 卡：feature.md

```markdown
# Fxx：名称

- 状态：Backlog
- 里程碑：待确认
- Chat1 / Chat2：待创建
- QA subagent：待委派
- 工作树 / 集成基线：待分配

## 目标与非目标
说明可观察结果和边界。

## 输入与依赖
列出上游验收、接口、样本和环境。

## 验收矩阵
| 编号 | 场景/输入 | 预期/阈值 | 验证方式 | 证据 | 结果 |
|---|---|---|---|---|---|
| AC-01 | 待填 | 待填 | 待填 | 待补 | 未执行 |

## 所有权与风险
产品文件、测试文件、共享接口、风险和决定。
```

## Chat1 启动说明

标题：`[KB][Fxx][Chat1] 名称｜总调度`

```text
你负责指定 feature 的总调度。先读项目方案、feature 卡和上游验收。
明确范围、依赖、接口、文件所有权、样本和验收；指定 Chat2 负责设计与实现。
接受或退回 design.md；跨 feature、schema 或预算变更交项目总台账。
QA 后直接读取报告、被测版本及证据，不以 Chat2 自报完成代替验收。
缺陷交 Chat2 修复，再由 QA 复测。记录决定与 acceptance.md。
全部验收和集成后检查通过才标 Done。启动前登记真实 Chat2 ID、工作树与消息授权。
```

## Chat2 启动说明

标题：`[KB][Fxx][Chat2] 名称｜设计与实现`

```text
你负责指定 feature 的设计和编码，向 Chat1 交付。先读项目文档并核对工作树及基线。
你不是独自在代码库工作，只修改分配文件，保留他人改动，共享接口变更由 Chat1 协调。
design.md 说明输入输出、数据变化、失败处理、资源预算、兼容与测试场景；Chat1 接受后实现。
完成开发自测后在本 Chat2 创建 QA subagent，给出验收矩阵、被测版本、环境及报告路径。
QA 独立找失败和缺口，默认只读产品代码；必要测试文件单独分配。
修复后让 QA 复测并保留失败历史，交 Chat1 直接复核。最终验收由 Chat1 决定。
```

## QA subagent 委派说明

任务名示例：`fxx_acceptance_tests`，必须在 Chat2 内创建。

```text
你负责该 feature 的独立验收，按需求确定输入、预期、边界和故障场景。
验证真实工具/API/客户端，不只按产品实现构造相同逻辑的断言。
你不是独自在代码库工作，不回退他人改动，默认只读产品代码，只写指定测试/证据目录。
使用测试副本，不对生产知识库做破坏性测试。
记录被测版本、环境、样本、命令、实际结果、退出码与证据；逐项 PASS/FAIL/NOT RUN。
失败写清复现、期望、实际与影响；保留失败和复测记录。
qa-report.md 应可被 Chat1 直接复核。不批准合并发布，不擅改验收范围。
未经明确授权不向其他用户聊天发送消息。
```

## QA 报告：qa-report.md

```markdown
# Fxx QA 报告

- 被测提交/快照：待填
- 环境/语料：待填
- 总结：PASS / FAIL / PARTIAL / NOT RUN

| 验收项 | 场景/命令 | 预期 | 实际 | 结果 | 证据 |
|---|---|---|---|---|---|
| AC-01 | 待填 | 待填 | 待填 | NOT RUN | 待补 |

## 缺陷与复测
编号、严重性、复现、修复版本和复测结果。

## 限制与清理
未测场景和影响；测试数据库、进程及文件清理结果。
```

## Chat1 验收：acceptance.md

```markdown
# Fxx 验收

- 结论：通过 / 退回 / 阻塞
- 需求/实现/QA 版本：待填
- 集成基线：待填
- 验收人：Fxx Chat1

## 验收证据
逐项核对 QA 与必要复核。

## 下游影响
可启动的 feature 和兼容条件。

## 遗留与下一步
问题影响、接受人、归属，以及集成/修复/等待条件。
```

按依赖分批创建聊天并登记真实 ID；启动说明必须包含具体 feature、文档路径、工作树和上下游。集成后测试须对应最终版本，不能用旧代码 PASS 覆盖新变化。
