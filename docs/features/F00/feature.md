## 评测契约与指标字典

设计须明确下列语义；字段名、CLI 参数和模块拆分由 Chat2 提出：

1. 每题有唯一 ID、类别、`dev` / `holdout` 划分、语料快照标识、答案存在性、人工可核对的相关证据 ID 集合。相关性单位明确为 document 或 chunk，不混算；若使用现有数值 ID，必须绑定数据库快照。相邻重复片段按既定单位去重。缺失标签与已确认无答案必须区分。
2. 真实题覆盖参数编号、中文问法、表格、相似型号、无答案五类；无法真实覆盖的类别标为未验证，并可用明确标记的合成样例验证工具本身。每类分别列总数、有效标签数、来源与划分，不用合成题补出真实覆盖率。
3. 默认报告 K=5，可配置并记录实际 K。对有答案题，Recall@K 为前 K 个结果中命中的不同相关证据数 / 全部已标相关证据数；MRR@K 为首个相关结果名次的倒数，无命中为 0。分组和总分采用逐题宏平均，分母与有效题数必须可见。未知相关集合完整性时标注受限召回，不能称全库召回。
4. 无答案题不参与 Recall/MRR；独立报告 empty-result rate = 成功且返回空结果题数 / 无答案题数，以及 false-positive rate = 成功且返回非空结果题数 / 无答案题数，另列 error rate = 错误题数 / 无答案题数，三者合计 1。错误不视为正确拒答。这里只评检索结果，不把它解释为生成答案的幻觉率。分母为 0 时输出 N/A/null 及原因，不输出假 0 或假 100%。
5. 本阶段默认不要求 nDCG；若采用，须给出分级相关性、gain、discount、ideal 排序与零分母口径，并提供独立算例。
6. P95 延迟单位 ms，逐请求计时；预热数量、重复次数、计时起止点、并发、K、请求顺序、样本量、错误/超时数须记录。建议 nearest-rank，即升序样本第 ceil(0.95N) 个，若用其他算法必须显式冻结。成功请求延迟与失败数量分开，不静默删掉失败。单次 CLI 总运行时间不能代替检索延迟。
7. 吞吐单位 successful queries/s = 测量窗口内成功请求数 / 测量窗口墙钟秒数，明确包括排队与否以及计时边界。串行函数入口只能称串行本地基线；未经实测不能称 API/MCP 端到端或目标并发能力。
8. 峰值内存明确进程范围、测量方式、采样周期和单位；Python 分配峰值、进程 RSS/工作集峰值分别命名，不能互相替代。无法测进程峰值时明确 N/A，并保留该验收缺口。
